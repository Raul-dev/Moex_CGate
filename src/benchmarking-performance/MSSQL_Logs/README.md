## **Сравнение стратегий логирования в MS SQL Server 2022 (Проект HttpMustDie)**

В данном документе представлено детальное описание **10 различных инженерных подходов** к организации логирования при высокой параллельной нагрузке (1000 потоков, размер пакета полезной нагрузки — 5 КБ).

## ---

**📑 Описание методов логирования**

## **1\. LocalTable (Тип 1\)**

Классическая прямая вставка (INSERT INTO) в стандартную дисковую таблицу.

> *   
> * **Принцип работы:** Данные пишутся напрямую в таблицу. Каждый поток блокирует страницу данных при обновлении B-Tree дерева.  
> * **Узкое место:** Жесткая конкуренция за последнюю страницу данных (**Last-Page Insert Contention / PAGELATCH\_EX**) и задержки журнала транзакций (WRITELOG).  
> * 

## **2\. LinkedServerTable (Тип 2\)**

Прямая вставка в таблицу, расположенную на другом сервере, через механизм Linked Server.

> *   
> * **Принцип работы:** Вызывается удаленная процедура или выполняется прямой INSERT через сетевой алиас.  
> * **Узкое место:** Огромный сетевой оверхед и использование протокола двухфазной фиксации транзакций (2PC / MSDTC), блокирующий вызывающие потоки.  
> * 

## **3\. RabbitMQPost (Тип 3\)**

Отправка лога во внешнюю очередь сообщений (RabbitMQ) напрямую из базы данных.

> *   
> * **Принцип работы:** Внутри процедуры вызывается высокопроизводительная SQL CLR-сборка, которая выступает продюсером и отправляет AMQP-пакет по сети.  
> * **Узкое место:** Сетевой стек и затраты ресурсов процессора на маршалинг данных внутри CLR-домена SQL Server.  
> * 

## **4\. InMemoryTable (Тип 4\)**

Запись логов в специализированную таблицу в оперативной памяти (In-Memory OLTP).

> *   
> * **Принцип работы:** Используются оптимизированные под RAM таблицы. Движок хранения полностью спроектирован по принципу **Lock-Free** (без блокировок и защелок страниц).  
> * **Узкое место:** Ограничено только скоростью работы шины оперативной памяти и процессора.  
> * 

## **5\. SequentialDiskTable (Тип 5\)**

Вставка в стандартную дисковую таблицу, оптимизированную под параллельные монотонные ключи.

> *   
> * **Принцип работы:** Кластеризованный индекс создается с включенной системной опцией OPTIMIZE\_FOR\_SEQUENTIAL\_KEY \= ON (доступно в SQL Server 2022).  
> * **Узкое место:** Сглаживает конкуренцию в памяти, но физическая скорость диска (I/O) при записи в .ldf журнал остается лимитирующим фактором.  
> * 

## **6\. ServiceBroker (Тип 6\)**

Использование внутренней встроенной асинхронной очереди MS SQL Server.

> *   
> * **Принцип работы:** Процедура делает мгновенный SEND сообщения в локальную очередь (Fire-and-Forget). Специальная фоновая активационная процедура вычитывает сообщения и сбрасывает их на диск **пачками (батчами)**.  
> * **Узкое место:** Затраты на сериализацию/десериализацию XML или JSON внутри очереди.  
> * 

## **7\. SESSION\_CONTEXT (Вариант 7\)**

Сохранение лога в оперативной памяти текущей сессии (SPID) подключения.

> *   
> * **Принцип работы:** Используется встроенный хэш-словарь сессии через sp\_set\_session\_context.  
> * **Узкое место:** Данные хранятся только в рамках текущего соединения и недоступны для чтения из других потоков.  
> * 

## **8\. TempTable (Вариант 8\)**

Нерегистрируемый или минимально регистрируемый лог через временные таблицы в tempdb.

> *   
> * **Принцип работы:** Вставка происходит в локальные или глобальные временные буферы, где транзакции практически не нагружают основной .ldf файл журнала.  
> * **Узкое место:** Общая пропускная способность базы данных tempdb при экстремальной нагрузке.  
> * 

## **9\. Extended Events / XEvents (Вариант 9\)**

Генерация кастомных расширенных событий ядра СУБД.

> *   
> * **Принцип работы:** Вызывается системная трассировка через sp\_trace\_generateevent. Ядро SQL Server асинхронно перехватывает событие и пишет в кольцевой буфер памяти.  
> * **Узкое место:** Неудобство извлечения данных штатными средствами T-SQL.  
> * 

## **10\. RAISERROR WITH NOWAIT (Вариант 10\)**

Прямой асинхронный стриминг текста лога обратно в сеть C\# сервису.

> *   
> * **Принцип работы:** Вызывается информационное сообщение (Severity \< 10\) с инструкцией немедленной отправки в сетевой буфер WITH NOWAIT. Нагрузка на хранилище БД полностью отсутствует.  
> * **Узкое место:** Скорость обработки входящего сетевого потока TDS-протокола на стороне C\# клиента.  
> *
